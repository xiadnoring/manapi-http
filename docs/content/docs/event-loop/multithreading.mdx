## Adding tasks

The ManapiHttp can work with additional threads which will do tasks if they are exists.
It's helpful when the library which the app is using contains ```std::mutex``` in their realization.
Because of this we need to reduce synchronous blocking in the Event Loop.

Adding a task to the ```taskpool``` will be shown below.

```c++
auto task = std::make_unique<manapi::function_task> ([] ()
    -> void { std::cout << "Hello World\n"; });
ctx->taskpool()->append_task(std::move(task));
```

<Callout title="Why std::unique_ptr ?">
    Because of many subclasses of manapi::task exists such as manapi::function_task and others we can't to
    store an object in the array, only its pointer.
</Callout>

## Number of threads

To set up the number of threads you need to edit the argument in ```manapi::async::context::create()``` like below.

```c++
auto ctx = manapi::async::context::create(std::thread::hardware_concurrency());
```

It will create the taskpool with the cpu hardware threads number as the number of threads in the application.


Also you can run the application without additional threads. Event Loop will execute tasks from the
taskpool itself.

```c++
/** without additional threads */
auto ctx = manapi::async::context::create(0);
```

## Class Task

If you'd like to create a custom Task subclass such as ```manapi::function_task```, you need know
that ```class Task``` must contains the public ```todo(...)``` method.

This method is called when the ```taskpool``` or ```eventloop``` is executing the task.
Therefore, all the important part of the class implementation must be in the ```todo(...)``` method.
