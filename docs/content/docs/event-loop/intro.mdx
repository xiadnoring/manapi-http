## About
Event Loop always takes one thread to watch and register new events and handlers.
But our app can be multi-threading.
Because of this we couldn't register new events directly from the other threads.
Therefore, we need to send an asynchronous signal about our new event and wait
for our event loop to process it.

<Callout title="What's a problem?">
Due to the race of the resources, we can't add some objects
to the container from the one thread and read them from the event loop thread at the same time.
It's impossible without synchronization systems such as ```std::mutex``` and ```std::atomic```.  
</Callout>

## A few opportunities
Some callbacks which we send to the event loop will be called from the event loop thread,
for this reason we can work with event loop without asynchronous methods and synchronization systems.

These features are provided by: synchronous ```timer```, public method ```custom_callback``` from the Event Loop and ```event callbacks```.
```c++
server.GET ("/", [&server, ctx] (REQ(req), RESP(resp)) -> manapi::future<void> {
    co_await ctx->timerpool()->async_append_timer_sync(500, [ctx] (manapi::timer t) -> void {
        /**
         * called in the event loop thread.
         * in other threads (which aren't an event loop) it will be undefined behavior (UB)
         */
        ctx->timerpool()->append_interval_sync(500, [ctx, index = 0] (manapi::timer t) mutable
            -> void { std::cout << std::format("interval: cnt {}\n", index++); });
    });

    co_return resp.text("Timer has been added");
});
```

<Callout title="Alert" type="error">
It works with synchronous callbacks only! If you try to do the same thing with
asynchronous callbacks, it will be undefined behavior.
</Callout>

Below is the code which contains undefined behavior (UB).
```c++
server.GET ("/", [&server, ctx] (REQ(req), RESP(resp)) -> manapi::future<void> {
    co_await ctx->timerpool()->async_append_timer_async(500, [ctx] (manapi::timer t) -> manapi::future<> {
        /**
         * undefined behavior!
         * don't do like this, otherwise the programm will crash soon.
         */
        ctx->timerpool()->append_interval_sync(500, [ctx, index = 0] (manapi::timer t) mutable
            -> void { std::cout << std::format("interval: cnt {}\n", index++); });
    });

    co_return resp.text("Timer has been added");
});
```

The correct way to add a synchronous interval will be shown below.
```c++
server.GET ("/", [&server, ctx] (REQ(req), RESP(resp)) -> manapi::future<void> {
    co_await ctx->timerpool()->async_append_timer_async(500, [ctx] (manapi::timer t) -> manapi::future<> {
        /**
         * that is the correct way.
         * no undefined behavior (UB).
         */
        co_await ctx->timerpool()->async_append_interval_sync(500, [ctx, index = 0] (manapi::timer t) mutable
            -> void { std::cout << std::format("interval: cnt {}\n", index++); });
    });

    co_return resp.text("Timer has been added");
});
```

<Callout title="I know what I'm doing!">
    If you 100% sure that the function will be called in the Event Loop thread,
    you could work with event loop directly.
    For example when you work with only one thread which is also an event loop. 
</Callout>
